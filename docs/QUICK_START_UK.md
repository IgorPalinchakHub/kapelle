# Kapelle: швидкий старт

Для простої фічі достатньо підготувати й погодити план, реалізувати зміну та перевірити результат:

```text
start -> погодження -> implement -> verify -> фінальне погодження
```

## 1. Підготувати план

```text
/kapelle:start <slug> "<опис задачі>"
```

Отримаєте компактний опис фічі та першу завершену наскрізну зміну:

- `spec.md` — що є зараз, що зміниться і як перевірити результат;
- `design.md` — які частини системи взаємодіють і що треба змінити технічно;
- `tasks.md` — один узгоджений блок роботи.

Новий або переглянутий план коротко фіксує:

- поточну поведінку, зміну, результат і те, що має залишитися незмінним;
- поточні й майбутні відповідальності компонентів;
- що змінюємо, коли роботу можна вважати виконаною та як це перевіримо.

Критерії приймання пов’язані з роботою та перевірками. Позначення `AC-NN` допомагають перевіряти
ці зв’язки в документах; у розмові Kapelle пояснює саму поведінку, а не просить розшифровувати коди.

Плагін сам переглядає, чи важливі для зміни помилки, права доступу, бізнесові правила, інтеграції
та вимоги до якості. Для простої зміни це коротка внутрішня перевірка, не анкета. Непотрібні
вимоги й числові цілі не вигадуються. Окремі описи сценаріїв, моделі або контракти додаються лише
коли потрібні для розуміння зміни; майбутні непогоджені можливості не деталізуються.

Діаграма додається лише коли словами важко пояснити взаємодії, порядок операцій чи переходи стану.
Вона супроводжується коротким поясненням. Проста зміна не отримує діаграму заради шаблону.

Якщо потрібне ваше рішення, Kapelle пояснює: що є зараз, що пропонується і які наслідки.
Посилання на документ лише доповнює пояснення. Зазвичай є рекомендований варіант з його мінусом
і одна альтернатива. Якщо рішення вже випливає з вашого запиту або правил проєкту, зайвого
запитання не буде.

Правки:

```text
/kapelle:start <slug> --revise "<що змінити>"
```

Підтвердження плану:

```text
/kapelle:start <slug> --approve
```

## 2. Реалізувати

```text
/kapelle:implement <slug> --checkpoint=workstream --validation=ask
```

Плагін реалізує погоджений результат через усі потрібні частини системи. Майбутні порожні сервіси
не створюються. Наявні тести використовуються повторно; рано додаються лише базові або справді
важливі перевірки, наприклад захист від подвійного списання. Це може бути короткий unit-тест.
Решта тестів залишається на завершення. Для простої зміни новий тест може бути непотрібним.

Наступну вимогу додавайте так:

```text
/kapelle:amend <slug> "<наступна бізнесова або технічна вимога>"
/kapelle:start <slug> --approve
/kapelle:implement <slug>
```

## 3. Дописати решту тестів і перевірити

```text
/kapelle:verify <slug> --validation=ask
```

`verify` звіряє реалізацію з документами, дописує решту потрібних тестів і виконує один погоджений
набір перевірок. Ранні тести не дублюються. Проста зміна залишається в компактних основних
документах; додаткових етапів для неї немає.

Якщо всі заплановані перевірки вже виконані вручну або в іншій сесії:

```text
/kapelle:verify <slug> --developer-verified "Усі заплановані перевірки пройдено."
```

Такий результат буде явно позначено як підтверджений вами, без спостереження виводу команд агентом.

Після PASS і ручної перевірки:

```text
/kapelle:verify <slug> --approve
```

## Якщо активна вимога змінилась

```text
/kapelle:amend <slug> "<нова вимога або feedback>"
```

## Статус або відновлення

```text
/kapelle:status <slug>
```

Для старої фічі Kapelle:

```text
/kapelle:migrate <slug>
/kapelle:migrate <slug> --apply
```
